# 词战：拼词对决 · Godot 原型

一个**可以直接玩**的原型：你对电脑，双方各五张随从，用抽到的词拼出技能，先手锁定、后手看见后应对，再沿同一条 20 秒时间轴结算。

## 怎么运行

- 双击 **`运行游戏.bat`**（会用 `D:\CodexTools\godot-4.7.1\` 里的 Godot 打开本项目）。
- 或者用 Godot 4.7.1 打开 `godot/project.godot`，按 F5。
- 字体用系统字体（微软雅黑）。如果要导出到没有中文字体的机器，需要把一个 CJK 字体放进项目并在 `scripts/ui/main.gd` 里换掉 `SystemFont`。

进游戏后：标题 →「开始对局」→ 构筑 → 抽词 → 调整 → 战斗 → 下一轮……「观战演示」是电脑对电脑。

## 规则速览（也写在游戏里的「玩法说明」）

| | |
|---|---|
| 目标 | 打倒一个随从，得到它生命上限那么多分；先到 **100 分**赢，最多 **10 轮**，到时比分数。倒下的随从**休整一整轮**后满血复出。全队同时倒下会送对方满额分数，但不结束比赛 |
| 构筑 | 五张卡。**100 点** = 五张卡的生命 + 所有技能里填入的数字（含持续秒数）。每张卡至多 2 个技能、1 个关键词 |
| 词 | 技能由词拼成，每个词卡只能用在一处。开局 12 词（保证一套攻击、一套应对）；之后每轮两袋各 20 词，先手先选一袋，另一袋归对手 |
| 操作费 | 宣告一个技能付：**5 点启动费 + 填入的数字 + 所用词卡价格**（卡上的 ◆）。词价：放大类 4、效果/触发类 1、语法词 0 |
| 行动点 | 开局 15，每轮 +15，最多存 60 |
| 起手 | 操作费每 10 点需要 1 秒起手。大招慢、小招快 |
| 一轮 | 抽词 →（各两次、交替、公开的）调整 → 先手锁定一个行动 → 后手看见后应对 → 20 秒时间轴结算。下一轮交换先手 |
| 同一秒的顺序 | 时间改动 → 沉默等状态 → 起手检查 → 建立监听/减伤 → 移除/换位 → 伤害治疗（含触发）→ 净值结算 → 倒下。同一秒的伤害与治疗按净值算 |
| 因果链 | 一个直接事件开一条链；链上**同一个监听器最多触发一次**。层数不设上限 |

**可见即所得**：卡面写每人受 20 点就是每人 20 点，没有隐藏修正；放大没有上限，拆招靠拼词。

三条由自动搜索逼出来的通用语法（见《强组合攻防演练报告》）：
- **「双倍 / 一半」适用于所有填入的数值**——不只伤害、治疗，也包括护盾吸收量、转移/转为的每人上限、打断/沉默的力度。攻守两边的放大因此对称。
- **「立即 / 之前」最早只能落到该节点自己的起手**（节点自己的数字+词价÷10），不能让大招绕过起手。
- **复制、接续的后续目标只能是单个随从**。否则「对全体造成 10 并复制给全体」会被平方放大成每人 60，和卡面读起来的 20 对不上。

### 拆招手段（举例，全是通用词拼出来的）

转移（把这次伤害转给别人，每个被保护者有上限数值）、转为治疗、回敬（按该次伤害回敬来源）、打断 / 沉默（带「力度」：只压制操作费 ≤ 1.25×力度的技能）、延后 / 提前（最晚第 19 秒）、减伤、护盾、治疗、易伤 / 狂振 / 升华 / 牵连、移除、换位、复制、分流、接续、择一、若/否则……共 107 个词，全部已实现（含立即、之前、同时、直到、本轮、已生效、剩余）。

## 两种卡牌编辑器

两个编辑器做出来的是**同一种牌**，可以互相接着改：

- **简单版**：从 21 个「招式模板」里选一个（单点打击、范围打击、分流、复制、汲取、治疗、减伤、护盾、施加状态、改道、转伤为疗、回敬、遗志、治疗引爆、见招收税、回合结算、时间术、驱散、换位……），像填空一样调参数；右边实时显示操作费、起手、占用点数，所需词缺了会标红。
- **复杂版**：直接拼节点树。每种节点（伤害、治疗、减伤、状态、移除、监听、时间术、换位、分流、接续、复制、若/否则、择一）都有表单，监听器里可以再装监听器，数值可以是填入的数字、引用（该次伤害、失去的生命、人数……）或运算（较高者、合计、差值）。

## 电脑对手

按“性格”（狂攻 / 守反 / 控场 / 连锁 / 均衡）构筑牌组、挑词袋；战斗里**逐个模拟**自己所有合法行动（每个目标、每个起手时刻），后手能看见你的宣告后再选最好的应对，先手会预判你的若干应对。它只用公开信息。

## 目录

```
project.godot
scenes/main.tscn            入口场景（只挂一个脚本）
data/words.tsv              词库（id 词 类别 稀有度 价格 已实现 权重 含义）
scripts/core/
  lexicon.gd                词库、词袋、开局词
  grammar.gd                技能节点树：所需词、费用、合法性、人话描述
  engine.gd                 结算引擎（纯规则，不含界面与发牌）
  recipes.gd                21 个招式模板（简单编辑器与 AI 共用）
  deck.gd                   牌组、预算与词的校验
scripts/game/match.gd       一局的流程（抽词、调整、宣告、结算），与界面无关
scripts/ai/ai.gd            电脑对手
scripts/ui/                 界面：标题、构筑、抽词、战斗、两个编辑器、组件
tests/                      测试与审计（见下）
```

**引擎与界面完全分离**：`core/` 和 `game/` 不引用任何界面，`tests/` 里的脚本可以无窗口批量跑；以后换界面或做联机，只需要调用 `match.gd` 与 `engine.gd`。

## 测试与工具

在 `godot/` 目录下，用 `Godot_v4.7.1-stable_win64_console.exe --headless --path . --script res://tests/xxx.gd`：

| 脚本 | 做什么 |
|---|---|
| `t_engine.gd` | 引擎单元测试（42 项：计费、减伤、净值、状态、监听、因果链、时间术、复出、计分……） |
| `t_ui_editors.gd` | 编辑器压力测试：遍历所有模板与节点类型 |
| `t_sim.gd` / `t_stats.gd -- N` | 电脑对电脑批量对局，统计胜率、局长、各类事件频率 |
| `t_trace.gd -- 种子` | 打印一局电脑对电脑的完整过程 |
| `t_audit.gd -- AP 输出` | **强组合 × 反制审计**（结果见上一级目录的《强组合攻防演练报告.md》） |
| `t_hunt.gd -- 数量 种子 输出 AP` | **无解进攻猎杀**：随机拼大量进攻，挑出得分高的，用反制库逐个试，列出没有任何反制能化解的结构 |
| `t_fuzz.gd -- 局数 种子` | 模糊测试：随机拼合法技能、随机对局，检查生命/行动点不越界、不死循环、无脚本错误 |
| `t_avail.gd -- 局数 输出` | 词袋可得率 |

带窗口的**真实鼠标点击**集成测试（需要窗口，不能 headless）：
`Godot_v4.7.1-stable_win64_console.exe --path . --write-movie x.png --fixed-fps 30 --quit-after 3000 -- --demo=clicktest`（抽词→选技能→点目标→宣告→下一轮）与 `--demo=clicktest2`（构筑→编辑器→装招→切标签→开始）。

带窗口的自动游玩（验证人类操作路径，不需要手动点）：
`Godot_v4.7.1-stable_win64_console.exe --headless --path . --quit-after 400000 -- --play`
调试截图：`--path . --write-movie out.png --fixed-fps 10 --quit-after 30 -- --demo=build|draft|battle|select|respond|editor|complex`。

## 已知限制（没做或没做好）

- 只有单人对电脑，没有联机；没有音效、没有美术资源（用字、颜色和代码绘制）。
- 「借用」（复制对手已宣告的技能）等新想法还没做。
- 电脑不会“读人”：它按模拟结果选，不猜你的下一步；构筑相对朴素。
- 平衡只做了一轮对决级别的审计（见报告），尚未做多轮、叠加反制的验证；数值（行动点节奏、词价、力度系数、计分目标）都是可调的初值。
- 开局 12 词能拼出的技能很少（通常 2 个），强组合要几轮后才出现；这是有意的节奏，但如果觉得慢可以提高起始词数。
- 窗口尺寸按 1600×900 设计，其它分辨率用拉伸适配，没有专门做小屏布局。
