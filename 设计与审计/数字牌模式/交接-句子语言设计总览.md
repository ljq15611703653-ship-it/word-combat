## 0. 一句话现状

- **用户的终极目标**：做出**可区分的 8 个小类、4 个大类（每大类 2 个小类）** 的玩法流派；之后根据这些流派的特点，**设计 4 个职业，每个职业只配两套卡组**。**职业现在先不定**，等流派自己长出来再针对性补特点。
- **核心理念（用户的话）**：「我们现在是用一套极其复杂的拼句做成了一个卡牌游戏，没有卡牌的快捷，也完全浪费了拼句游戏的自由。我们一定要把自由度利用起来。」
- **解决思路**：让**句子本身就是规则**——句子可以读写句子、引用词类、设时间窗口、挂在场上（长期生效）、被移除；词本身变成可交互的东西；基础词只留最基础的和「自指」的，其余全是进阶词，进组牌预算，这样构筑才有选择。
- **做到哪了**：
  1. 新的**拼句界面**（手牌条 + 名牌即句子条）已完成并在主分支（打电脑可用）；
  2. **句子规则的原型**（`src/lab`）做过 9 轮迭代，但它是**手写模板**的版本，只是验证方向的替身；
  3. 用户已要求**重做原型**：不硬编码流派，只给电脑目标让它自己长出流派（见 §5）。这一步**还没开始**，是接手后第一件事。
  4. **真实游戏引擎**（`src/engine`）还是旧语法，新词、长期句子都没移植。

## 1. 设计决策日志（按主题；每条都是用户拍板或明确认同的）

### 1.1 为什么改（诊断）
- 现在拼句「点开面板—点词—确认」，没有互动感；效果粒度和普通卡牌没区别；最优句式永远是「选择 1 敌方 造成 N」，句式同质化。
- 我们一开始想的「更多句式、更多职业、调平衡」都被用户判定为「更麻烦的卡牌游戏」。真正的问题是**粒度**：效果的输入输出应该是**句子的结构本身**（词类、词数、段数、词序、累计次数）。

### 1.2 核心：句子即规则（用户的原话要点）
- **不存在「任务牌」「状态牌」这种另外的牌种。句子本身就是任务。** 带「每当 / 若 / 不得 / 持续」的句子不会一次放完，留在场上继续生效；顶部显示的就是这些**还活着的句子本身**，敌我可见（**不要猜、不要暗**）。
- **没有「状态」这个东西，只有「状态词」**（易伤、灼烧、衰弱：效果会留下来的词）。类别本身也是可拼的词：可以写「移除一句带有灼烧词的话」。
- 所有逻辑能**自由组合**：每当、数量、不得（**必须带轮次**）。
- 读写范围：已出的句子（个数 / 次数 / 种类数）、正在拼的句子（自引用）、之后要出的句子；对象敌我皆可。可以只对自己生效。
- 例子（用户给的味道）：对方上一句含某类词；某词在另一词前面；本局对方已用过 N 次某词；你的下一句越长伤害越大；接下来三句若包含 A、B 和 C 则……；攒爆：「N 轮后，造成（引用量）×2」。

### 1.3 数字牌 = 价格（定价的总原则）
- 所有数字（窗口大小、倍率、触发上限、收紧、效果大小、等待轮数）都吃数字牌；**1 免费**；**牌面 ≥ 数字就能用**（用同面值太苛刻，原型里实测凑不出带多个数字的句子）；**牌越大越强**，在任何位置都成立。
- **不要死板的「长度付费」**；也**不再单独做「价值公式」**：数字靠数字牌、非数字的宽窄靠词的价格（范围越宽的词越贵）、段数靠行动点。
- 数字永远**跟在一个角色词后面**：造成/恢复/减伤 N、重复 N、持续 N、之前/以后 N 轮/句、**收紧 N**、**至多 N 次**、第 N 句、N 轮后、倍率。
- **收紧**（门槛）：「xx 词超过几个」。门槛有基线，**收紧牌越大越容易触发**，所以越强（这样大牌=强的方向统一）。预览里同时显示牌面和换算后的门槛。收紧是**单独的词**，可选，不说就用基线。
- **至多 N 次**：触发上限，每轮最多触发几次；**不说默认一次**。是单独的词。
- 触发产生的效果**不会再触发别的触发**（一层封顶，防循环）。
- 出手的随从倒下，它挂着的长期句子就断了（和现有「续」一致）。

### 1.4 窗口、判断、条件
- **窗口 = 方向词（之前 / 以后）+ N + 单位（轮 / 句）**，**不写死「上一轮」「本局」**：上一句 = 之前 1 句，本局 = 之前一个大 N（被数字牌稀缺卡住）。
- 句式：`若 + 窗口 + 主体（对方/我方）+ 判断词 + 对象 + 收紧 M，则 + 效果`。
- **判断词只有四个：存在、不存在、成功、失败。**
  - **去掉「若没有」**，改成「若 不存在」；存在/不存在可以引用任何东西（词、类、状态词、句子）。
  - 成功/失败**只能拼在条件句里**，免费，指「前一段的效果有没有真的发生」（伤害被挡掉 = 失败）。
- 「第 N 句」位置词：按**宣告顺序**，吃数字牌。**不要「首句 / 末句」。**
- 「已经」（看过去）和「接下来」（看未来）判断时机不同：过去的条件在句子生效那一刻判；未来的条件让句子留在场上，窗口里发生了才触发（= 长期句子）。界面要让玩家看出这句是「马上判」还是「留着等」。
- 空窗口：开局没有任何句子时，「存在」为假、「不存在」为真（已知小漏洞，先接受，模拟里看会不会被滥用）。

### 1.5 词的分类与基础 / 进阶
- **基础词也有类别。** 基础词只留两种：**真基础**（免费、不冷却：选择、自身、敌方、友方、造成、恢复；数字牌 1）和**自指**（引用别的东西的词：窗口、判断、条件、事件、引用名词、引用量、主体）。
- **自指词要花钱，用完冷却一轮，和数字牌同一套机制**（一张会冷却的牌）。具体要不要花行动点、价格多少：**到时候测试决定**，范围宽窄决定价格。结构词、对象词免费。
- **其余全是进阶词**，进组牌预算（沿用 18 点）、有限张数，否则「构筑屁都不是」。完整词表见 `句子规则原型.md` 的「词表草案 v1」（价格和张数只是测试起点）。
- **生命变动类**：伤害、恢复的并集；可以单独引用伤害或恢复，也可以引用「生命变动」（范围更宽，更贵）。
- **伤害需要是真正的词**（引用位置显式：「受到伤害」「累计伤害」「无视 减伤」）；基础句里隐含（「造成 3」不强制写成「造成 3 伤害」，避免冗长）。

### 1.6 无视
- 统一叫「无视」，是**一个词**，后面要接一个**类别词**说明无视什么：攻击上「造成 3，无视 减伤」；防守上「无视 灼烧 N 轮」（无视挂在自己身上的状态词，要带持续轮数）。
- 原型里目前是简化版（见 §4.5），要改成「无视 + 类别词」。

### 1.7 其他已定
- **倒下**触发：新增事件词（现在游戏里没有「当……倒下」，只有【不屈】和「有人倒下掷骰子」）。
- **移除**：自由移除（不限制词），靠价格兜底（目标越宽、句子越长越贵）；它同时给「挂上就无解」留了反制出路。
- 「**不得**」：必须带轮次；做成「违者受罚」而不是真禁止（不要让人挫败）。
- **攒爆**：引用量两种都要——等待轮数、等待期间某事件发生的次数；加一个单独的关键词「**兑现**」（提前结算，按已等的时间算）。
- **每轮宣告时间限制**：先做接口（`setTimeLimit` / `onTimeout`），联机版覆盖 `onTimeout` 才能做服务端判超时。

### 1.8 拼句界面（已实现）
- 拼句时**底部手牌条**（基础词 / 进阶词 / 数字牌），**拖到随从头顶的名牌上装配**；**名牌就是句子条**，没有面板。
- 拖时合法位置**亮成一个个缝**，最近的高亮；点一下词牌 = 装到最后一个合法位置；句子条里的牌**拖出来 = 拿掉，后面依赖它的牌一起掉下来**；拖到别的缝 = 换位置，只允许合法位置。
- **辅助轮直接拆**（横版里已无）；「随从拖到目标自动填句」的拖线 / 框选**已删**。
- 选目标：拼好后点「拼好了 → 去选目标」，再像以前一样点场上的随从；选目标 / 定起手秒数时**名牌继续显示这句话 + 已选目标**；有「撤回上一个目标」「返回修改句子」（句子原样保留）。

### 1.9 被否决的想法（别再提）
- **改写**（会挫败）；**暗词 / 猜**（要的是可读、可推理）；**硬禁令**（要付代价的可选择）；**对仗 / 排比奖励**；**借词**；**全场规则（双方都受影响）**；**首句 / 末句**；**「契约」或「任务牌」这种单独的牌种**；一开始我提的「以句为靶」里的改写；**拖线 / 框选 / 随从拖到目标**；**辅助轮**。

### 1.10 开放问题（还没定）
- **状态词要不要改名**（用户说「灼烧这种要重新起名」，但还没定改不改、怎么改）。
- **战报**（一局打完把所有句子排成一篇文字）：我提过，用户没表态。
- 用户让调参时提到「**词的种族**」：不确定是指「类别」还是别的。
- 自指词到底花不花行动点、花多少：等测试。
- 下限类条件（超过 N）是否需要镜像换算：已通过「收紧」解决，不再需要。

## 4. 句子规则原型（`web3d/src/lab/`，只在模拟里跑）

### 4.1 它是什么、和真实引擎差在哪
- 对真实引擎的**简化版**：6 个随从（每方 3 个），每个随从每轮一句或不出手，双方轮流宣告（先手每轮交替）；每轮 20 秒，句子在**起手秒数**生效（起手时间 = 1 + (段数−1)×`WIND_CL` + (最大数字−1)×`WIND_N`），结算按 (秒, 阶段[移除→减伤→恢复→伤害→兑现], 宣告顺序)；过热、行动点、数字牌冷却沿用全灭模式的规则（见 `rules.ts` 的 `P`）。
- 没有职业；没有真实的「卡组构筑」（用「流派 = 允许用哪些句式」代替）；没有类别体系、窗口词、存在/不存在（用「每当/若没有/定时」的写死形式）。
- 文件：`rules.ts`（参数 `P` + 类型；环境变量 `LAB='{"HP":8}'` 可覆盖）、`sim.ts`（状态、宣告、结算）、`ai.ts`（候选句 + 推演）、`run.ts`（对阵矩阵）、`tune.ts`（随机搜参 / 爬山）、`sweep.sh`（扫参）。
- 运行：`cd web3d && npx tsx src/lab/run.ts all 40`（40 局 × 15 对阵，约 15 秒，4 进程并行）；`run.ts one A B N seed`；`tune.ts 次数 局数 [基础JSON] [种子]`，`CLIMB=1` 开爬山。

### 4.2 电脑（`ai.ts`）
- 每次轮到自己：生成候选句（含起手秒数）→ 对每个候选，克隆状态、宣告它、让**默认策略**（贪心，会躲陷阱、会优先打带长期句子的随从、血少会上减伤）把本轮和接下来 2 轮打完（推演 3 轮），按 `10×(存活数差) + 1.2×(总血量差)` 加权求和（权重 1 / 0.7 / 0.5）估值，选最高的。
- 流派（`ATK / TURTLE / TRAP / BURST / FULL`）= 允许用的句式族（单段伤害和并人人都有）。**这是手写的，要被取代**（§5）。

### 4.3 参数（当前默认 = 爬山 1 的最优一组，损失 28.5）
HP 11，AP0 5，APINC 5，APCAP 10，HEAT_FROM 4，HEALC 2，SHC 3，STAND 1，THR0 1，AND 0，CASH 1，REMOVE 1，REMOVE_ANY 4，PIERCE 1，SPEC 99，CARDS0 [2,2,3]，SCHEDULE {3:[2],5:[3],7:[4]}，EXACT false，TL 20，WIND_CL 1，WIND_N 1。

### 4.4 迭代记录与关键发现（原始数据在 `原型数据/`）
| 轮 | 改动 | 结果 / 发现 |
|---|---|---|
| 0 | 第一版规则；流派里只有 ATK 有「并」 | 攻击流对谁都 77–95%：**测试不公平**（只有它有多段句） |
| 1 | 所有流派都有基础句 | 攻击流反过来被吊打（16–38%）：纯攻击不用防，当时数值下不划算 |
| 2 | 数字牌从「同面值」改成「牌面 ≥ 数字」 | 特殊句（每当/定时）几乎没人用（每局 0.1～0.2 次）：**同面值要求让带多个数字的句子凑不出** |
| 3 | 修电脑：候选抽样名额被基础句占满，特殊句根本没被看到 | 特殊句用到每局 0.3～1.2 次：**这是电脑的问题，不是设计** |
| 4 | **恢复 / 减伤改成 2 点行动点（SHC 3）** | 攻击流回到 40～50%；**发现：减伤太便宜是攻击流崩的主因** |
| 5 | 门槛基线 THR0 1、特殊句行动点 STAND 1 | 特殊句每局 2～3 次；一句挂长期句子要占一个随从的位置，所以效果要比一次攻击强才有人用 |
| 6 | 流派 = 牌组承诺（只能用自己那族句式） | 出现剪刀石头布；曾因攻击流独占「并」而通吃，改成人人有「并」 |
| 7 | 40 组随机搜参 | 最优损失 22.5：龟缩 > 陷阱 > 爆发 > 龟缩 的循环出现；**攻击流没有猎物** |
| 8 | 爬山 36 步 | 损失 28.5；攻击流仍无猎物 → **光调参数解决不了，要改句式设计** |
| 9 | **加回起手秒数（20 秒）+ 无视 + 若失败转火** | 攻击流有猎物：对龟缩 82%、陷阱 63%；天敌是定时爆发（被打到 16%）；平均 5.14 轮。**真实游戏里攻击流的天然优势（出手早）原型曾丢掉** |
| 10 | 带时间轴的爬山 2 | 跑到 24/40 被我停掉，最优损失约 43.8，没意义（旧的手写流派） |
- 其他记录：血量扫参：HP 6 局太短（约 4 轮）、8 约 4.8 轮、10～11 约 5.1 轮；SPEC（能带的特殊句数）扫参结论不稳定（40～60 局噪声 ±6%）。
- **损失函数**（`tune.ts` 的 `score`）：各流派对其余流派的平均胜率在 46–54%；每个流派有猎物（某对阵 ≥ 60%）和天敌（≤ 40%）；无极端对阵（>80% 或 <20%）；FULL（什么都能用）平均 50–65%；平均轮数 4.5～6.2；陷阱流每局触发 ≥ 1.5，爆发流每局爆发 ≥ 1.0。
- 速度：约 0.25 秒/局（4 核 swiftshader 机器上）。

### 4.5 已知局限（接手要知道）
1. 候选句子是**手写模板**，不是从语法生成；所以「流派」是我预先划的，不是长出来的。
2. 没有真正的构筑（卡组、预算、张数）。
3. 无视是简化版；没有窗口词、存在/不存在、类别词、引用词冷却、第 N 句、不得、词序条件、句子长度引用量。
4. 结算做了阶段简化；选目标时机、择流（事后定目标）没有模拟。
5. 电脑的推演只看 3 轮；贪心默认策略太单一，会让推演高估某些写法。
6. 噪声大（每格 40～60 局，±6%）。

## 5. 下一步：重做原型（用户明确要求，**还没开始**）

**用户的要求**：做新原型，重新跑；**不硬编码流派**，只告诉电脑目标是什么、让它多尝试、**让它自己长出流派**；职业先不定，看长出哪些流派再补特点；界面同步做（凡不依赖引擎的部件）。

### 5.1 终极目标
**可区分的 8 个小类，4 个大类，每大类 2 个小类**。之后据此做 **4 个职业，每职业两套卡组**。所以新原型要能**自动聚类出流派**并报告它们的特点。

### 5.2 我准备的做法（已和用户口头对齐，用户未提异议）
1. **重写原型引擎为一个小型语言解释器**：句子 = 抽象语法树（条件 + 窗口 + 主体 + 判断词 + 对象 + 效果），效果由引擎按词的含义**组合计算**，不再写死「这是陷阱句式」。这个共享的 AST 同时是真实引擎的移植目标和界面（长期句子栏、费用显示）的数据结构。
2. **候选句子从语法自动生成**（给定手里的词和牌，枚举或随机采样所有合法句子），不再手写模板。
3. **两层搜索**：
   - **内层：卡组自动进化**。预算内（18 点）随机抽进阶词卡组，自我对战，保留赢得多的，变异 / 交叉；用**多样性保护**（相似的卡组互相竞争、行为描述符分格，类似 MAP-Elites）避免全部收敛到同一副。
   - **外层：规则参数**（价格、张数、血量、行动点）由人 + 我一起调，目标是「元目标」。
4. **元目标（给电脑的目标）**：①没有一副卡组通吃；②有强攻击型的卡组存在，克制某些流派，也容易被另一些克制（互相有猎物 / 天敌）；③每局约 5 轮、句子不越来越长；④用到的词足够多样。
5. **事后聚类**：用卡组构成 + 行为统计（攻击词占比、长期句子数、平均句长、无视 / 移除使用率……）聚成大类 / 小类，给出每类的胜率矩阵和特点；目标是能分出 **4 大类 × 2 小类**。
6. **电脑变聪明**：通用推演算法，不分流派；每轮先判断「不平衡是设计问题还是电脑不会玩」，再改电脑（这是用户明确的要求）。**算力是限制**：4 核、0.25 秒/局，一代进化可能十几分钟——先低精度筛选（少局数、短推演），再高精度验证最后几副。

### 5.3 建议的执行顺序
1. 定共享 AST（`web3d/src/lab/ast.ts` 之类），把「已定规则清单」里所有句式写成 AST 节点；
2. 解释器：结算、窗口、判断词、长期句子、事件、冷却、无视 + 对象、不得（违者受罚）、第 N 句、词序条件、句子长度引用量；
3. 通用候选生成 + 通用 AI；
4. 卡组进化 + 聚类 + 报告；
5. 外层调规则；每个阶段汇报一次；
6. 原型稳定后移植到 `src/engine`，界面接上（顶部长期句子栏、按类别分组的手牌条、实时费用、悬停预览、联机、教程）。
