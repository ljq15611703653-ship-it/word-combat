## 一、我读到的真实语义（实现的依据）

- **命中结算顺序**（`engine.ts hit`）：基础伤害 + 目标的易伤级别 → 出手者的衰弱（减 min(级别, 伤害)）→ 目标本轮的减伤（每一击都减，可叠加，轮初清零）→ 血痂（不移植）→ **首挡**（敌方打中且还剩伤害：整下挡掉，本轮用掉）→ **转移**（敌方打中且还剩伤害：全部转给出手的人，那一份不再经过对方的任何减免；出手者已倒下则落空）→ 扣血。灼烧、过热不走这条路（不被首挡、转移挡）。
- **重复**：`for r < rep { for 每个目标 { hit } }`，每一击单独走上面一整套（所以易伤/衰弱/减伤每击都生效，首挡只挡第一击）。
- **hp ≤ 0 的随从不会立刻倒下**：`hit` 对 hp ≤ 0 的目标直接返回 0；倒下只在**每一秒的出手结束后**（`koCheck`）判定，也在过热之后再判一次。判定时有「不屈」且本轮没用过 → hp = 1，否则倒下。**同一秒里被打到 0 血的随从还能出手**（`down` 要到秒末才置位），之后的秒才落空。
- **同一秒的顺序**：只有「每一段都是减伤/转移/恢复」的句子（`isDef`）排在前面，其余按宣告先后（`ord`）；一句话整句一起生效（段按顺序）。**移除并不比伤害先**（和「保护先于移除」的说法不同，真实代码里没有这条）。
- **状态**：施放时已有 → 级别 +1、结束轮 = max(原结束轮, 当前轮 + 持续数 − 1)；没有 → 1 级、结束轮 = 当前轮 + 持续数 − 1，来源记第一个施放的人。每轮开始（`beginRound`）：当前轮 > 结束轮 → 删除，否则**级别 +1**。句子里的数字只是**持续轮数**（占数字牌），级别不是数字。灼烧在每轮结算最后（时间轴之后、过热之前）掉 `级别` 点，不经过任何减免。
- **延后**：对方本轮**已宣告且还没生效**的一句，`start += N`；> TIMELINE 就整句落空；已生效的无效。AP 价 1，数字 N 占牌。宣告时只能选对方已宣告的句子。
- **转移**：AP 价 2，目标是己方随从（个数占数字牌），本轮有效。
- **移除**：目标是一个敌人：清掉它的减伤、转移，删掉它挂着的续（`R.conts`）。不拆状态。AP 价 1，没有数字。
- **起手**：最早第 `1 + 词类段数 + (段数 − 1)` 秒（词类段 = 状态/转移/延后/移除），与数字大小无关；`start ≤ TIMELINE(10)`。
- **行动点**：整句花费 = `BASE_COST(1)` + 各进阶词价格（状态 1、转移 2、延后 1、移除 1；造成/恢复/减伤本身 0）+ 每多一段 `AND_COST(2)`；开局 5、每轮（第 2 轮起）+4、上限 10，没花完的带到下一轮。
- **数字牌**：每个 ≥2 的数字（目标个数、伤害/恢复量、重复次数、状态持续、延后秒数）各占一张**面值正好相等**的牌；开局没有牌，第 3/5/7 轮各发一张 2/3/4（可反复用，用完隔一轮才能再用）。
- **先后手**：轮流宣告，第 1 轮先手可指定（默认随机），之后每轮交替。
- **过热**：第 3 轮起每轮结束，每个活着的随从受 `(轮数 − 2)` 点挡不住的伤害，不记击倒功劳，不屈有效；双方最后的随从同时倒下，比**过热前**的总生命。

新词在词表里的临时位置（`params.ts` 的 `ADV`，只有对应开关打开才进随机卡组/词表）：转移 价 3 张数 2（载荷面积 3×2），延后 价 2 张数 2；状态词、移除保持原有。首挡/不屈是关键词，不进载荷板。

**`D:/wc/deckbuilder/words.js` 需要同步**（这次没改）：加 转移（AP 2、数字=目标个数）、延后（AP 1、数字=秒数）、重复（base 词、数字占牌）、两个关键词的选择；状态词注明「级别每次施放 +1、每轮自动 +1，数字只是持续轮数」；移除注明「拆减伤、转移、续」。

## 三、未移植（按要求）

- 四个职业（并/续/择/血）的天赋、限制、计分与「成长」、目标完成度、超时三级判定里的第三项（成长）——lab2 超时仍是活着人数 → 总生命 → 平局。
- 择流的「目标事后再定」与待定附加费；血流用血付行动点；并流一句 7 段/起手不变晚；续流的【持续】子句（lab2 里「长期句子」不是它）。
- 骰子（掉血≥4 或有随从倒下掷两颗）、成长阶梯发牌（10/25/45/70% 各两张 2/3/4/5）。**后果：REAL 配置里数字牌比真实游戏少得多**（只有保底的 2、3、4 各一张）。

## 四、仍有差异（没动，或有意保留新设计）

1. **目标的确定时机**：lab2 的 `lowFoe/lowMe/选择 N 个` 在**生效那一刻**取血最低的；真实游戏的目标是宣告时就指定的（只有择流事后再定）。电脑在 lab2 里大量用 `lowFoe`，所以打法比真人灵活。`unit(u)` 指定目标已对齐（REAL 下落空不换人）。
2. **词表/卡组**：真实卡组正好 10 张进阶词（同名 ≤2，只有 易伤/灼烧/衰弱/转移/延后/移除）；lab2 用载荷预算（`BUDGET`）和自己的词表（并、减伤、定时、不得、累计……保留新设计），REAL 配置只是在其上加开关。
3. **并/段数上限**：真实非并职业一句最多 3 段、多一段花 2 点；lab2 要卡组里带「并」（≤3 张）、多一段花 `AND`，没有 3 段硬上限。
4. **长期句子、引用量、全程、位置、定时、无视、兑现、成功/失败连环**：lab2 新设计，真实引擎没有。REAL 配置下仍可用；平衡实验里它们和真实规则同时存在。
5. **减伤的 `无视`、`ignore` 等 lab2 独有修饰**与真实的首挡/转移叠加时，只保证「无视减伤」不绕过首挡、转移。
6. **宣告校验**：lab2 `declare` 把过早的起手秒自动提到最早允许的秒，真实是直接拒绝；效果等价。
7. **结算里的细节**：血痂（真实代码里有但没有任何词能产生）、`R.eff/kob` 等计分字段、`cont` 子句都没有对应物。
8. **随机性**：真实的骰子、AI 的 `choose` 与 lab2 电脑不同；平均轮数的对照只能看总体（见冒烟结果）。
