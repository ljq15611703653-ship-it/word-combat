# 句子海量挖掘 + 决策表蒸馏：说明

代码：`web3d/src/lab2/mine/`（命令与耗时见该目录 README.md）。产物在 `D:/wc/mine/`（`leaderboard.md`、`decision_table.md` 等）。

## 1. 怎么用

四步，每步一个脚本，都从 `web3d/` 运行 `node --import tsx src/lab2/mine/<x>.ts`：

1. `mine.ts` 生成句子库：以手册句（`playbookNamed`）和 `gen.ts` 的语法随机句为种子，做变异（改数字、换对象/主体/窗口/目标/动词、数字↔引用量、加/删/换序一段）和交叉；修补语法（目标合法、窗口合法）；按结构规范化 key 去重；只保留「原则上说得出口」的句子（行动点、数字牌、自指词在参照资源状态下够，进阶词不超过单副卡组限额和预算）。「普通攻击/自保」限量（它们是基线）。
2. `states.ts` 局面样本库：5 种电脑配置（含自由/普通/手册模式）、随机卡组的自我对战，在每次「轮到某方宣告」前存局面，再按（轮次段 × 位置 × 对方有无长期句）分层抽样；存成 JSONL，`st` 就是 `St` 的 JSON（`St` 全是纯数据，`JSON.parse` 直接还原，不需要回放）。
3. `funnel.ts` 漏斗：边际价值 = 该句的推演估值 − 同局面同随从下「最好的朴素攻击 1~3」的推演估值（推演逻辑与 `ai.ts` 的 `rollout` 相同，估值用 `evaluate`）。评估时双方卡组设成不限（只看句子本身强不强），资源（行动点/数字牌/自指词冷却）用局面里的真实值，说不出口的局面按 0。三层：粗筛（少量局面、深度 1~2、一种配置）→ 精筛（更多局面）→ 复验（全部局面 × 3 种电脑配置，各自的留牌/留行动点权重与深度）。通过 = 每种配置下排名都在复验集前 40%、适用点数 ≥ 8、每种配置下适用时平均边际 > 0。输出总榜、家族榜、位置榜。
4. `distill.ts` 蒸馏：让带推演的电脑在大量局面里从（基础句 + 手册句 + 随机抽的 16 句精选库句）中选句子（保留真实卡组），把每次选择归到家族（含「不出手」），提取 40 个局面特征，自写 CART 决策树（训练/测试按局面划分，避免泄漏），导出 JSON 与中文规则清单；另外给每个主要家族训练一棵「一对多」小树，列「什么时候倾向用它」。

## 2. 各步骤耗时（6 进程，当前规则 rules.json/rules2.json）

| 步骤 | 规模 | 耗时 |
|---|---|---|
| 挖掘 | 1 万句 / 10 万句 | 3 秒 / 5 秒（10 万句 95 MB） |
| 局面库 | 300 / 1200 个 | 49 秒 / 203 秒 |
| 漏斗 | 1 万句 × 300 局面 × 3 配置 | 20~55 秒（机器负载不同） |
| 漏斗 | 10 万句 × 300 局面 × 3 配置 | 178 秒（第 1 层 122 秒） |
| 蒸馏 | 1200 局面 × 3 配置 = 3600 决策 | 26 秒 |
| 100 万句（外推） | 同上 | 约 30~40 分钟；内存 ~1 GB/进程，建议分批 |

## 3. 示例输出摘要（1 万句 × 300 局面 × 3 配置；蒸馏用 1200 局面）

漏斗：1 万 → 第 1 层 930 → 第 2 层 316 → 复验通过 114。10 万句：→ 6702 → 2223 → 769。

最有意思的发现：

1. **「全体 × 引用量」是数值爆炸**。形如「敌方全体受伤 [之前 2 轮我方打出的伤害累计]×2」，费 4~5，适用时平均边际约 +700~850（≈ 一句话改写胜负，估值里一场胜负是 ±1000），三种配置结论完全一致，适用率约 55%（第 2 轮起几乎都能用）。10 万句里通过复验的 769 句有 490 句是这一类。原因：引用量没有封顶，「全体」又让每个敌人各吃一份。已把含此结构的句子单列成榜，不挤占总榜；设计上需要对「引用量 + 全体」封顶或加价。「全程」版本（之前全程）更夸张：适用时胜普通句 100%（平均边际 ~1270），只是前几轮没得引用，适用率 9%。
2. **禁令/陷阱/荆棘/无人则/无视长期/移除/多段攻防，在 10 万句里几乎没有一句稳定通过复验**（禁令 1 句，其余 0）。这类句子靠「威慑」起作用，而推演里的对手是朴素默认策略（只会打最低血或回血、不会被吓住也不会绕开），所以单句价值被低估。这是工具的盲区，也提示：这几类的强弱不能靠本漏斗下结论，要靠对战（对手也是会学的电脑）。
3. **决策表**（3600 条决策，测试集 1020 条）：决策树准确率 **48%**，永远猜最常见类 = 20%，按频率随机猜 = 11%，前两名命中 65%；同一局面在 3 种配置下选同一家族的比例 **86%**。规则被资源主导：行动点 ≥ 3 且牌面 ≥3 的牌 ≥ 3 张时，词位（位置 0）倾向选【连环】（占 76%，测试集命中 78%），数位/第三位倾向选【全体引用量】或【连环】；行动点 ≤ 0 → 不出手；行动点 1~2 → 普通攻击；有「引用量词」且行动点 ≥ 4 → 全体引用量。「读上一句」类的叶子在测试集上命中很低（0%~25%），说明那几条规则是过拟合，已如实列出。

## 4. 已知局限

- **全部结论只代表「电脑打电脑」**：推演里对手和后续都是朴素默认策略；真人和会反制的对手不同。
- 边际价值对噪声敏感；局面只有 300 个，位置榜每个位置 64/103/133 个点；`选项价值` 把「不能说」按 0，所以它同时混合了「强」和「常能用」。
- 评估时把卡组设成不限；真实对局里能带什么词受预算限制，所以「强但贵（占很多进阶词）」的句子实战没那么强。
- 起手秒只试两个（最早、偏晚），没有搜索最优时机；「读上一句」类对时机敏感，可能被低估。
- 家族是按结构硬分的（优先级：全程引用 > 禁令 > 连环 > 接力 > 读上一句 > 状态连击 > …），一句话只归一类。
- 决策表里的卡组特征（`dk*`）和资源特征会直接限制能选什么，规则里出现它们是「没有词/没有资源就不能说」，不全是策略。
- 变异只在 AST 层面保证语法合法，不保证「对玩家有意思」；性质不同的海量近似句（只差数字）会让排行榜里出现很多近亲，看家族榜比看总榜更有信息量。
- 规则还在迭代：每次规则改动后需重跑全部四步（句子库的可说性判定、局面库、评估都依赖规则）。1 万句/300 局面的整条链在 2 分钟内可重跑。
- 100 万句的运行是外推，未实测；内存是主要风险。
