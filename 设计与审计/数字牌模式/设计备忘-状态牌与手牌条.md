# 设计备忘：状态牌框架 + 手牌条拼句（讨论中，尚未实现）

> 状态：只是讨论记录，**先别做**。当前先讨论具体玩法。

## 起因（诊断）
- 现在是「用一套极其复杂的拼句做成卡牌游戏」：没有卡牌的快，也没用上拼句的自由。
- 词本身没有可交互性；效果的粒度和普通卡牌没区别。

## 一、状态牌框架（粒度问题）
- 效果的输入、输出都是**句子本身的结构**：词、词类、词数、段数、词序、累计次数。
- 统一的「状态牌」挂在屏幕顶部，**敌我可见**。不只是契约，可以是：本局某词计数、限制敌方下一句、
  「之后每一句若不用某词则……」、小任务（接下来三句含某些词则……）等。可只对自己、可敌我都生效。
- 读写范围：已出的句子（个数/次数/种类数）、正在拼的句子（自引用）、之后要出的句子；对象敌我皆可。
- 基础设施（先做，内容后定）：句子特征层；挂钩位置（拼句时 / 结算时 / 观察）；寿命与范围；顶部显示。
- 原则：每句至少有即时价值；投资有利息也有风险；同时在场数量与文字长度要克制；一切可见，**不要猜、不要暗**。
- **明确不要**：改写（挫败）、暗词/猜；敌方限制不做硬禁止，做成可违反但付代价。
- 不要过早定成某一个具体玩法（契约只是其中一种内容）。

## 二、手牌条拼句（互动感问题）
- 所有词排成一排（底部或右侧），像炉石：拖出来装上、拖下去就拿掉；装上后自动排序，可在合法位置内手动调。
- **句子条直接放在随从头顶的名牌上**，去掉拼句面板；对手的句子同样在他的名牌上一张张出现。
- 已定的三个难点：
  1. 句子条在名牌上，不再有面板。
  2. 拿掉中间的词时，依赖它的词一起掉下来（要有动画）。
  3. 手动调顺序只允许在合法位置之间移动；拖词时所有合法落点亮起。
- **辅助轮直接拆**；新手教程之后再改。
- **刚做好的「随从拖到目标自动填句」（拖线/框选）不要了**，将被手牌条取代（实现时一并移除 `src/drag/`、Composer.dragTo/boxTargets、Game.dragDrop/dragBox 与教程里的拖拽教学）。
- 难点提醒：名牌太小，拖词时要临时放大、长句换行；拼句引擎需要「按位置插入 / 拿掉并连带依赖 / 列出合法落点」接口。
