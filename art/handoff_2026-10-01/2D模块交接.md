# 2D 卡面素材交接

本包只提供素材，不修改游戏脚本或现有配置，不放入 `godot/assets/`。原始生成脚本为 `source/2d_tools/build_assets.py`；运行它会重新生成同名 PNG。全部为原创几何插画，参考视频的深紫星象、浅色珐琅、暖金高光与稀有卡演出气质，未沿用视频中的角色、文字或标识。

## 已有接口，复制即可加载

- `assets/cards/<proc>.png`：17 件独立 2D 配件，256×256 RGBA，透明背景。对应 `godot/data/appearance.json` 的每个唯一 `proc`；颜色已画入 PNG，不依赖代码染色。此目录下其他人的 `body_剑/盾/咒/弓/魂.png` 是独立身体图。配件与身体必须分别保留，不要烘成一张完整人物。
- `assets/icons/<kind>.png`：20 种基础 UI 图标，256×256 RGBA，浅色单色透明，供 `godot/scripts/ui/icon.gd` 在不同场合染色。
- `preview_2d.png`：配件和图标总览；`preview_small_scale.png`：实际 32–34 像素可读性；`preview_card_assembly.png`：按目前 `card_face.gd` 的挂点坐标做的 156×206 卡面四倍放大示意。预览文件不属于运行时素材。

## 另做的可选视觉件

`optional/` 下有纵向牌背 `card_back_512x768.png`、透明边框 `card_frame_common_512x768.png` / `card_frame_rare_512x768.png`，以及 `summon_circle_512.png`、`reveal_rays_512.png`、`stardust_512.png`。这些只是给后续界面与特效接线用的分层纹理，**目前没有对应的自动加载入口**；不要误当成已在游戏内生效。牌背、卡框等不应和人物配件合并。

## 集成前必须核对的两处现状

1. `card_face.gd` 的 `aura` 和 `ghost` 分支目前直接调用程序绘制，并不读取同名 PNG。要用到本包的 `ring_double.png` 和 `afterimage.png`，集成人需要改这两个分支的取图逻辑；素材本身已备齐。
2. 三种免疫共用 `amulet`，在 `appearance.json` 中靠 `color` 区分。当前 `card_face.gd` 的 PNG 路径不会应用该颜色，因此原样复制会让三种免疫的吊坠看起来相同。集成时需要对这张 PNG 染色，或者按规则拆成三张；不要让玩家丢失颜色线索。
3. 当前 `SLOT_POS` 是占位图标的坐标。按原位叠上这套完整小饰物时，披风、盾、剑看起来偏离身体，详见 `preview_card_assembly.png`。集成时应根据五种身体的实际轮廓微调卡面挂点，不能靠把配件和身体画死在同一张图里掩盖问题。只调 2D 卡面挂点，不涉及 3D 碰撞体或战斗逻辑。

可将 `assets/cards/` 与 `assets/icons/` 按同名相对路径放入 `godot/assets/`，然后启动 Godot 检查。生成脚本会检查所有 17 个 `proc` 与 `appearance.json` 完全吻合，并逐张验证 256×256、RGBA、透明像素。
